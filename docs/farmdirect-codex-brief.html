১. নতুন Registration Requirements

01

NID number দিয়ে registration

এখনো নেই
  • Client এবং Farmer, দুই registration form-এই NID field required করতে হবে।
  • Email optional হবে; email না থাকলেও account তৈরি হতে হবে। Email-এর জায়গায় NID-কে primary login identifier হিসেবে ব্যবহার করতে হবে।
  • NID server-side validate করতে হবে এবং duplicate NID দিয়ে দ্বিতীয় account আটকাতে হবে। Accepted digit-length/format বাংলাদেশি NID policy অনুযায়ী নির্ধারণ করতে হবে।
  • NID ব্যক্তিগত তথ্য: database-এ নিরাপদে রাখুন, logs বা public pages-এ প্রকাশ করবেন না, display করলে mask করুন।
  • Existing email-based accounts যেন lock out না হয়; login-এ NID এবং পুরোনো email দুটোই support করার migration strategy রাখুন।
02

District + Upazila বাধ্যতামূলক

আংশিক আছে
  • দুই registration form-এই District এবং Upazila required হবে; address field-কে Upazila-এর বিকল্প হিসেবে ব্যবহার করা যাবে না।
  • Upazila আলাদা field হিসেবে users এবং farmers record-এ সংরক্ষণ করতে হবে। Client registration বর্তমানে upazila save করে না; Farmer registration-এ address-কে upazila হিসেবে কপি করা হচ্ছে।
  • District বদলালে সংশ্লিষ্ট Upazila দেখানো উত্তম। নির্ভরযোগ্য upazila dataset না থাকলে প্রথম ধাপে required text/select input ব্যবহার করুন এবং data source স্পষ্ট রাখুন।
  • Profile edit ও farmer location pages-এও নতুন তথ্য যেন হারিয়ে না যায়, তা যাচাই করুন।
03

District search এবং A–Z ordering

Sort আছে, search নেই
  • District picker-এ searchable/filterable control দিন, যাতে নাম লিখে district দ্রুত খুঁজে পাওয়া যায়।
  • Initial list এবং filtered results সবসময় district name অনুযায়ী A–Z হবে। Search করলে sort order ভাঙা যাবে না।
  • বর্তমান registration controller-এ district-গুলো server-side A–Z sort হয়; shared picker এখন plain HTML select। বিদ্যমান ordering বজায় রেখে search যোগ করুন।
Interpretation: A–Z requirement-টি district picker/search-এর জন্য ধরা হয়েছে। Product search results-এর sorting আলাদা requirement হলে implementation-এর আগে নিশ্চিত করতে হবে।

IMPLEMENTATION BACKLOGPRIORITY ORDER

২. Review থেকে পাওয়া বাকি কাজ

নিচের কাজগুলো current code review-তে দেখা gap; registration changes-এর সঙ্গে এগুলোও backlog-এ রাখুন।

P0 · Farmer approval flow শেষ করা

Farmer signup account-কে inactive/pending করে, কিন্তু admin user-management page demo data দেখায়। Real approval/rejection actions যোগ করতে হবে; approve হলে account active হবে, reject হলে status/reason সংরক্ষিত হবে এবং farmer-কে ফল জানাতে হবে।

P0 · Payment status সঠিক করা

bKash/Nagad/Card gateway verification ছাড়া order বর্তমানে paid/completed হয়ে যায়। Gateway/API callback যাচাই না হওয়া পর্যন্ত online payment pending রাখুন; success, failure, retry, duplicate callback এবং refund flow implement ও test করুন।

P1 · Admin panel-কে database-backed করা

Dashboard, users/roles, categories, transactions, reports, backup এবং settings বর্তমানে static/demo data বা browser localStorage-নির্ভর। Real models/queries, authorized actions, validation, pagination ও audit trail প্রয়োজন।

P1 · Inventory shipment consistency

Order ship করার আগে warehouse-এ পুরো quantity আছে কি না validate করুন। Shortage হলে shipment block হবে এবং data partial decrement হবে না; প্রয়োজন হলে transaction/locking দিয়ে atomic update করুন।

P1 · Automated tests এবং build ঠিক করা

বর্তমান feature test homepage-এ 500 দেয়, কারণ in-memory SQLite test database-এ schema migrate হয় না। Test setup-এ migrations/seed data যোগ করে registration, login, farmer approval, order, payment ও inventory workflow cover করুন।

`npm run build`-ও বর্তমান environment-এ verify হয়নি: `vite` executable পাওয়া যায়নি। Dependencies install করে clean build নিশ্চিত করুন।

P2 · User-facing completion

  • Client, Farmer এবং Manager notifications demo data থেকে real persisted notifications-এ নিন।
  • Contact message database-এ জমা হয়; admin inbox, read/unread state এবং reply workflow যোগ করুন।
  • Password reset flow যোগ করুন; current routes-এ এটি নেই।
  • Farmer profile-এর Follow action-কে বাস্তবভাবে persist করুন, অথবা feature প্রস্তুত না হওয়া পর্যন্ত UI থেকে সরান।

DEFINITION OF DONETESTABLE ACCEPTANCE

৩. Acceptance Checklist

প্রতিটি item complete বলতে UI, server validation, database persistence এবং automated test-এ একই behavior নিশ্চিত হওয়া বোঝাবে।

  • Client ও Farmer email ছাড়া NID দিয়ে registration করতে পারে।
  • NID অনুপস্থিত, invalid বা duplicate হলে server request reject করে; duplicate account তৈরি হয় না।
  • Email দেওয়া optional; দেওয়া হলে existing email uniqueness behavior বজায় থাকে।
  • দুই registration form-এ District ও Upazila বাধ্যতামূলক এবং আলাদা database field-এ save হয়।
  • District picker-এ search/filter কাজ করে; unfiltered এবং filtered option list A–Z থাকে।
  • Existing email-based account দিয়ে login চলে; নতুন account NID দিয়ে login করতে পারে।
  • Farmer request admin/authorized user approve বা reject করতে পারে; approval-এর পর farmer login করতে পারে।
  • Online payment verification না হওয়া পর্যন্ত order paid নয়; callback-এর ফল transaction status-এ সঠিকভাবে প্রতিফলিত হয়।
  • Insufficient warehouse stock-এ order ship হয় না এবং কোনো stock row partial update হয় না।
  • `php artisan test` সফল; registration এবং critical order/payment flow-এর feature tests আছে।
  • Dependencies install করার পর `npm run build` সফল।

৪. Codex-কে দেওয়ার নির্দেশনা

এই brief অনুযায়ী প্রথমে registration/NID/location/A–Z requirements implement করুন। Existing Laravel patterns ও accounts compatibility বজায় রাখুন। Database migration, validation, views, authentication, profile forms এবং automated tests একই change-এ update করুন। তারপর P0 backlog-এর farmer approval ও payment correctness ঠিক করুন। কোনো demo/localStorage action-কে production action হিসেবে রেখে দেবেন না। শেষে focused tests, full test suite এবং frontend build চালিয়ে ফল report করুন।

৫. Implementation Order

  1. NID schema + secure storage + backward-compatible login strategy।
  2. Client/Farmer form, server validation, District search/A–Z, Upazila persistence।
  3. Farmer approval flow এবং admin action।
  4. Payment verification ও warehouse stock consistency।
  5. Test suite, real admin pages, notifications/contact/password reset backlog।

Sensitive NID data production-এ নেওয়ার আগে access control, retention, masking, encryption এবং applicable privacy/legal requirements review করতে হবে।
